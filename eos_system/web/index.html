MODEL MAPPING

操作系统概念如何迁移？

场景类比
操作系统与卫星调度的概念对应及边界
课程概念卫星场景中的对应
作业 / Job一次观测请求包含目标、优先级、所需曝光时长和候选窗口。
处理资源卫星及其观测载荷可并行服务不同任务；卫星是被建模的资源，不是本机 CPU 或 Worker。
就绪条件当前受检的可行观测机会进入窗口还不够，还需满足资源、转向与曝光要求。
服务时间任务要求的完整曝光时长观测不可拆成 CPU 时间片抢占后续拍摄。
上下文切换开销卫星姿态转向与稳定时间按当前场景与公共模型计算，不能照搬固定 CPU 切换常数。
I/O 与资源分配下传、地面站与存储等约束有地面站时才安排下传；课程资源预算不是完整电池动力学。

SYSTEM IMPLEMENTATION

系统真正实现了什么？

实际机制
PROCESS

进程管理

Controller 派发实验；独立 Worker 求解。运行详情展示后端记录的 PID、尝试次数与终态。

IPC & SYNC

通信与同步互斥

通过 Pipe / JSON 协议传递命令与结果；文件锁、槽位租约和事务保护共享状态。

LIFECYCLE

取消、超时与回收

先协作取消，再按有界期限回收进程；取消和失败有独立终态，不冒充成功结果。

PERSISTENCE

持久化与有限恢复

SQLite 保存配置、状态、计划与指标；可选独立 Daemon 提供有界监护与恢复。

STRATEGY & EVALUATION

把课程策略放到同一条件下比较

打开策略比较 →

经典 OS 策略迁移

FCFS 关注到达顺序，SJF 关注曝光时长，Priority 关注任务优先级，EDF / LLF 关注窗口截止期与松弛度，HRRN 综合等待与服务时间。

简单对照与小组方法

随机可行插入、卫星轮询提供简单对照；DARTIS、RABAS、CAABS、LAVIS 展示不同搜索与学习路线。卫星轮询不是 CPU 时间片 RR。

观察策略的收益与代价

完成率与任务收益越高越好；TM 是包含未完成惩罚的归一化等待指标，不是平均周转时间；RT 是求解耗时，不是卫星执行时长。

实验状态如何流转？查看队列、进程与核验的边界

QUEUED 等待派发 → STARTING 启动进程 → RUNNING 求解 → VERIFYING 核验 → SUCCEEDED 结果保存。另有 FAILED、TIMED_OUT、CANCELLED 等终态。

这是算法运行 Run 的状态机，不是卫星的 CPU 进程状态图。工程曝光采样通过也不等于严格连续区间认证。
