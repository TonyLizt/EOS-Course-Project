# 小组协作与维护

以README和当前API/源码为准；历史讨论稿不再作为必须实现的新指令。组长李泽同协调公共接口、模型、数据库和集成影响。

## 每次修改

1. 确认工作区状态；未提交文件先备份，不用reset/clean覆盖他人工作。
2. 同步已合并main，从main开本次功能分支。项目本地目录由成员自行选择，不把个人盘符写入代码默认值。
3. 单一主题修改，中文注释解释职责、边界与原因；能复用现有组件就复用，不能复制一套不受维护的Controller/物理规则。
4. 更新README或对应主题文档，并在COURSE_SETUP追加一条大阶段记录；小修改合并到相关阶段，不为每个按钮新增一份交接稿。
5. 跑对应测试和真实链路检查，保留失败、跳过与限制。算法/物理修改须特别检查冻结模型和来源身份。
6. 提交、推送功能分支，提PR；组员审核并解决冲突后merge main，不直接用旧源码整目录覆盖main。
7. 合并后再同步main，清理本次临时文件。大数据、模型、DB与wheel另发资源包，核对SHA。

组长当前使用Codex时要求每阶段结束先询问是否commit；push必须另有授权。执行过的Git命令要提供一份清单。普通开发者可按小组约定自主提交自己的分支。

## 变更边界

| 内容 | 必须同时核对 |
|---|---|
| Solver/算法 | Registry参数、统一结果、取消/预算、JSON IPC、共享约束和独立核验 |
| Worker/Controller | 进程身份、队列/锁、终态、正常关闭、崩溃恢复；不能由Worker直接写成功指标 |
| API/SQLite | 请求/响应、状态和事务、迁移、旧记录读取/导出、OpenAPI/ER说明 |
| 场景/物理 | 历元、姿态合同、窗口生成身份、谱系、模型域；不改旧数据或侧车伪造通过 |
| 模型 | 新ID、新制品、训练划分/配置和成本；不覆盖冻结权重或改manifest绕过不匹配 |
| 前端 | 原控件ID/行为、配置保留、排序/导出、Gantt/Cesium；展示不代替核验 |
| 部署 | 不固化个人路径；干净Linux目录安装、模型/场景自检及真实实验，保留原运行DB备份 |

两个不可变历史证据文件及data/registry用于回归，不当成当前设计文档修改。算法推理身份绑定的文件不要仅为排版重写；必要重构须重新说明模型兼容与实验版本。
