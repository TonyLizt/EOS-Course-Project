## 清理规则

- 先记录文件体积、依赖和是否被代码/测试/文档引用。未知用途先归档，不凭文件名删除。
- Git可以恢复已提交内容，但不能替代未提交文件、LFS对象、本地模型、数据库及外部分发资源的备份。
- 不把虚拟环境、运行数据库、回放缓存和旧实验副本打进源码包。
- 原EOS-Bench的实际复用内核与开源归属保留；移除确定无用的原研究输出、重复入口和示例需更新引用/回归。
- 将历史小改动文档合并为少量可读主题与大迭代记录，必要审计证据单独归档，不把失败记录改写为成功。
- 原实验数据库暂不删除，先迁移/备份并核对；生成的大缓存可按可重建性清理，不能不分用途递归删除整个运行目录。

## 第3阶段：部署与分发

交付源码ZIP＋资源ZIP。资源包含66场景、4个LAVIS制品、Orekit ZIP及Linux x86_64/CPython3.10 wheels；公开开发训练数据另有可选ZIP。资源逐文件校验后才安装；不覆盖不同字节的既有输入。源码与资源版本必须匹配，不能从尚未推送的远端取得本地新功能。

WSL运行目录约定：

| 位置 | 用途与保留原则 |
|---|---|
| `.venv/` | 本机安装的依赖；不复制给其他机器 |
| `config.json` | 相对数据/Orekit路径及默认端口；命令行/环境覆盖 |
| `datasets/`、`models/`、`resources/` | 输入、冻结制品、Orekit；哈希不变 |
| `wheels/` | 可再次离线安装的依赖缓存 |
| `results.sqlite3`、锁/租约/状态 | 现行核心约定的运行根目录文件；不为美观迁走，不手删活锁 |
| `artifacts/history/` | 旧专题实验输出，保留原内容 |
| `artifacts/releases/v1/` | 发布实测记录 |
| `logs/history/` | 关闭后的旧日志；当前Daemon按原合同写运行根目录 |
| `exports/`、`replays/` | 导出与回放缓存；与数据库记录联动清理 |

已有SQLite与回放保留，备份后也不擅自重置实验。只移动无活跃引用的历史专题结果和已关闭日志；输入数据源绝对路径、现有模型和数据库位置不变。临时验收目录在停止隔离服务、保存证据后删除，不长期留第二套venv。

换目录验收使用全新venv、资源安装与仅离线wheels；验证6联调场景可列举、19算法就绪，以及FCFS/CAABS/RABAS/DARTIS/LAVIS真实Worker、独立核验、事务入库、JSON/CSV与批量统计、回放READY、页面路由和Daemon生命周期。它是部署联调，不替换已冻结的1140次成绩。详细测试计数和遗留检查结果见交付目录验收记录。
