# LAVIS 第二轮学习优化方案与执行记录

基点：main f49e755；分支 feat/lavis-learning-optimization-v2；2026-10-20。

## 目标与预定方法

保持统一场景、物理约束和原24维特征，训练能够适应 expanded 候选分布的新排序模型。探索“观测决策造成的任务机会损失”监督，区别于 v3 的有界双续排回归。独立模型ID，不覆盖旧权重。

只从既有124个训练场景/92来源组构造样本；52个公开验证场景用于开发选择，最终20测试保持封存。旧验证已多次用于开发，不是未见测试；本轮不新增场景。所有标签、模型和大报告写运行目录独立子目录，提交Git只保留代码和小型证据摘要。

### 标签

在合法部分计划中采样候选；假设加入候选后重新调用共享约束检查全池，计算其他任务的可达机会损失。主项是完全失去机会的任务数，辅项是可选位置减少比例；这是单步机会成本代理，不是最优完成数或真实回报。仅对实际计算的候选打标签，未采样候选不当负例，同状态中心化，相同来源与状态等权。

采样轨迹先复用旧模型 configured 可达计划，再在 expanded 池中对空/中/后期状态计算标签。属于明确的离策略监督；不声称在新模型可达分布上完成训练。采样兼顾模型高分、冲突压力和稳定随机覆盖，固定种子42。每来源至多4状态，每状态12候选；先小样本试运行估计代价。

### 有界模型比较

固定三组：HGB 15叶、HGB 31叶（180轮/0.05/min_leaf5/L2=1）、ExtraTrees 96树/min_leaf3，seed42，单线程。均只使用训练标签。统一 expanded + greedy 的10秒预算在全部52验证上比较，保护原20场景完成数，再看高冲突家族宏TCR与任务数；如均不改善就不推荐。

入选后与旧v3在相同 expanded + multistart、30秒预算下复测；独立采样物理核验与真实Worker/导出验收。若预算/计算成本需要调整，应在记录中说明，不改写预定结果。旧默认策略不自动替换，新推荐需明确依据。

## 交付

离线生成/训练/复现实验工具、机制与来源隔离测试、新受控模型（若有改善）、验证及失败记录、README/COURSE_SETUP/交接说明。停止源码修改后再冻结新模型；不把新权重伪装成旧权重，不修改旧场景合同，不自动提交推送。

## 实现说明（结果产生前记录）

- 新工具 `scripts/train_lavis_opportunity.py collect|train`，训练划分由既有 `training.splits()` 白名单读取，继续校验场景SHA与谱系。
- 监督原始值：`-完全失去候选的其他任务数 - 0.25 × 其他任务候选减少比例的均值`。已选任务自身的其他位置不计损失；逐候选重新核验全池，不能基于未经证明的单调性删减核验。
- 标签按真实场景SHA与部分计划生成状态哈希；同状态中心化，平标签状态不用于排序训练。新标签显式声明 `lavis-opportunity-cost-v1`，不冒充旧双续排标签。
- 在线仍由冻结模型输出排序值，再走原共享约束及Controller独立核验，没有把离线教师或硬编码机会成本函数放进在线选择器。
- 模型登记继续验证完整源码指纹、依赖、权重SHA与24维特征；仅增加明确的新标签合同分支，未知协议仍拒绝。旧模型与旧策略兼容入口保留。
- 新比较工具 `scripts/compare_lavis_models.py` 只允许公开验证ID，支持同条件新旧模型对照和Orekit采样；临时Orekit文件由上下文自动清理。
- 隔离HTTP工具增加 `--model-id` 和 `--base-main`，避免复制一套验收服务。模型ID必须是登记ID，不能是路径。

标签签收：124场景/92来源组，5898行/496状态；5040行/420状态具备排序信号，覆盖91来源组；约33.9MB，生成合计199.26秒。旧v3曾有46个有效训练来源组，但扩大有效覆盖本身不等于效果提升。原始标签保存在运行目录 `derived/lavis-opportunity-v4/`。

## 使用与重新训练

完成验收后，网页勾选LAVIS，冻结模型选择 `lavis-v4-opportunity`，候选策略 `expanded`。快速模式 `greedy` 的验证预算为10秒；多分支模式 `multistart` 的独立比较采用30秒，结果另列，不混用两个预算。保持完成率目标、earliest、默认约束、无地面站。原默认模型/策略保持兼容，需显式选择新模型。

文件放在 `<EOS_RUNTIME_DIR>/models/lavis/lavis-v4-opportunity/`。其他组员需要复制完整目录，并使用同版代码和requirements-ml依赖；单独clone仓库不会下载权重。不要手改manifest指纹或用新模型覆盖旧ID。

复现训练时在WSL已激活的项目虚拟环境中设置好 `EOS_RUNTIME_DIR`，用新输出目录和新模型ID：

```bash
python -B scripts/train_lavis_opportunity.py collect \
  --dataset "$EOS_RUNTIME_DIR/datasets/eos-course-v1" \
  --extra-dataset "$EOS_RUNTIME_DIR/datasets/lavis-conflict-v1" \
  --output "$EOS_RUNTIME_DIR/derived/lavis-opportunity-retrain"
python -B scripts/train_lavis_opportunity.py train \
  --dataset "$EOS_RUNTIME_DIR/datasets/eos-course-v1" \
  --extra-dataset "$EOS_RUNTIME_DIR/datasets/lavis-conflict-v1" \
  --output "$EOS_RUNTIME_DIR/derived/lavis-opportunity-retrain" \
  --model-id lavis-v4-opportunity-r2
```

collect可用 `--limit 8` 试运行，然后不带limit补齐；train必须具有完整训练白名单标签。已完成的标签只在来源、协议和源码检查一致时复用。输出不允许进入场景目录或仓库，已有模型ID拒绝覆盖。若三组均未通过门槛，只写失败报告、不登记新模型。

## 冻结模型全量独立验收

新模型通过真实模型登记/加载入口重新运行全部52个公开验证场景，greedy + expanded、10秒预算、seed42。**52/52 SAMPLED_PHYSICAL_PASS**，0失败；原20验证715/900，高冲突32验证1849/2944、16家族宏TCR61.2637%。相对于旧v3冻结预测器对照1808/2944、60.0474%，实际增加41任务、家族宏TCR增加约1.22个百分点。

1849是本轮冻结加载后的实际成绩，不能用训练内存模型选型的1864替代。部分大场景触及预算；内存候选模型在外层统一配置线程池，而生产FrozenPredictor每批预测还有线程池控制开销，预算边界和运行时差异会影响完成数。本轮不在训练后修改推理源码或补写模型指纹来追平成绩。后续若优化预测开销，应另行冻结并重新验收。

核验仍使用原课程姿态、地球遮挡、转向、资源与Orekit全曝光采样；未放宽物理规则。有限采样不等于严格连续认证。原始结果 `derived/lavis-opportunity-v4/independent-full-validation.json` 含每场景SHA、模型快照和实际指标，Orekit临时副本已自动清理。

数据划分沿用已有任务来源合同；原始eos-course-v1存在共享星座/历元，不能宣称本轮证明了跨轨道泛化。新增高冲突家族沿用独立来源划分，最终20测试未读取；所有本轮验证都属于开发验证。

## 最新传统算法参照与边界

本轮额外串行重跑最新main的RABAS，使用相同来源、约束、目标、种子和时间预算；以下RABAS数据为求解器返回成绩，本轮没有对这60次基线返回逐次做独立Orekit复验，不冒称全部物理认证。

- 全52验证、10秒：RABAS原20完成715/900，高冲突32完成1905/2944、家族宏TCR61.8652%；新v4冻结单路径为715/1849、61.2637%。因此不能说v4已全面超过RABAS。
- 固定8验证、30秒：RABAS普通四例148、高冲突四例209；v4多分支为148/218。RABAS四个高冲突逐例22/77/20/90，v4为25/76/23/94；F034仍少1任务。
- 新v4相对旧v3，16个高冲突家族宏TCR中9提高、1持平、6下降，不保证每个来源均改进。
- 最大10秒预算差距为HC-F044-V2：v4完成60、RABAS114；该场景足以解释全量56任务差距中的54。需将搜索开销和决策质量分开分析，不靠增加单个场景预算后回填总表来宣称全量领先。

后续优先关注冻结预测的批次线程控制开销、拥挤大池的特征计算，以及真正的模型可达轨迹训练；它们需要独立实验与新冻结，不能悄悄改写本轮已验收模型。
