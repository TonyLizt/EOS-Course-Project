## 1. 本轮目标和来源定义

新建48个独立合成轨道家族，每家族2个目标/负载变体，共96场景：32家族64场景训练、16家族32场景高冲突验证。加上原60训练和20验证后，训练为124场景/92来源家族，验证为52场景/36来源家族。原有最终20测试继续冻结。

**新增数据不裁剪、复制、改名或扰动既有验证/测试场景。** 六根数从新seed空间随机生成，历元使用2025年12月，目标来自自身新轨道的可观测走廊；不读取既有测试目标、窗口、成绩或私有种子。两变体共用轨道父家族，必须同组，不把两个文件当两个独立轨道来源。

原60训练/20验证仍保留原协议的固定星座共享关系；新数据具有独立的新轨道家族，不能借此把旧数据的限制改写成跨星座独立测试。物理模型、通用相机能力和生成规则可共享，不将这些通用实现等同于任务母场景。

数据隔离检查只读取最终测试冻结索引中的ID/lineage/SHA，保存索引SHA和计数用于排重；不打开测试场景，也不读取测试目标/标签。公开新增数据说明不披露私有测试来源列表。

## 2. 高冲突如何构造

- 四个预先声明的分层：成对轨道走廊、短曝光密集任务、长曝光竞争、混合负载。每档训练8家族、验证4家族。
- 每家族4/6/8颗全新合成卫星，时域2/3/4小时；64至128任务，曝光5至90秒。成对卫星有小幅独立轨道差异，形成替代机会与独占边缘。
- 轨道提案仅按真实Orekit物理条件选择合法走廊锚点，记录每对卫星实际提案编号、锚点及选择规则。保持原45度姿态边界，不为出数据放宽物理门禁。
- 目标沿自身轨道地面走廊和横向偏移分布，让同星任务时间竞争；少量背景任务和零窗口任务保留，不根据算法完成数删数据。
- 全时域5秒窗口扫描、原退出二分边界、每场景最多10段完整曝光0.05秒含端点检查。有限网格/采样仍不构成连续区间证明。
- 冲突统计来自相同LAVIS有限候选池的同星不同任务观测区间重叠，不把此代理量说成完整资源冲突图或所有连续时刻机会。

## 4. 标签与训练改进

- 使用已有24维特征、同一在线求解器及候选池，旧lavis-v1权重和推理身份保持有效。
- 先构造合法可达轨迹，再从其真实长度中选中间状态；避免高冲突实例提前结束，采样计划却一直落在不可达的第20/40步。
- 候选采样先比较同任务高低压力/替代卫星，再补稀缺任务；标签仍是两条固定续排的归一化完成数均值，未评候选不打负标签。
- 状态哈希纳入场景SHA，避免同轨道兄弟场景的空计划/同名任务碰撞去重。训练权重仍按父家族、状态、候选分层等权。
- 仅从训练白名单生成标签，模型超参数在原20验证与新增32验证上比较。新验证按16个家族等权汇总，不把兄弟文件当独立样本。
- 模型选择先保护原验证完成数，再看高冲突家族宏平均TCR。最终测试不参与任何阈值或参数选择。
- 增加相同参数、相同采样器下“仅原训练数据/加高冲突训练数据”的控制比较；同时保留规则、常数、随机、静态特征及旧模型比较。

## 5. 复现和存储

所有大JSON、标签和权重在运行目录，不进入Git。新数据独立目录`<EOS_RUNTIME_DIR>/datasets/lavis-conflict-v1`，新派生目录`<EOS_RUNTIME_DIR>/derived/lavis-conflict-v2`，新模型ID`lavis-v2-conflict`。旧模型与原80场景不覆盖。

```bash
python -B scripts/build_conflict_dataset.py --output "$EOS_RUNTIME_DIR/datasets/lavis-conflict-v1" --base-dataset "$EOS_RUNTIME_DIR/datasets/eos-course-v1" --freeze-index "$EOS_RUNTIME_DIR/datasets/eos-course-v1/final_test/test_freeze.json" --finalize
python -B scripts/lavis.py dataset --dataset "$EOS_RUNTIME_DIR/datasets/eos-course-v1" --extra-dataset "$EOS_RUNTIME_DIR/datasets/lavis-conflict-v1" --output "$EOS_RUNTIME_DIR/derived/lavis-conflict-v2"
python -B scripts/lavis.py train --dataset "$EOS_RUNTIME_DIR/datasets/eos-course-v1" --extra-dataset "$EOS_RUNTIME_DIR/datasets/lavis-conflict-v1" --output "$EOS_RUNTIME_DIR/derived/lavis-conflict-v2" --model-id lavis-v2-conflict --budget 15
```

使用本机已安装课程/Orekit/requirements-ml依赖的WSL虚拟环境并先设置EOS_RUNTIME_DIR。生成和训练期间不要修改对应生产源码。新模型ID不可覆盖；原有冻结测试索引必须由数据负责人提供，只用于隔离核查。

原目录CLI仍默认60/20流程；显式传extra-dataset才启用扩充。已有v1标签缓存保留原协议，不强改为v2样本。

## 6. 验收范围

专项回归覆盖：48家族32/16预分配、四档平衡、新轨道可复现、测试索引不读场景、同轨道家族不能跨训练验证、兄弟状态哈希隔离、短可达轨迹中间状态，以及旧分布保护优先级。真实数据/模型结果以本文件后续签收记录为准。

## 8. 直接扩充的失败记录与相对训练目标

直接使用7890行基础标签训练8组配置，得到实验模型 `lavis-v2-conflict`。原验证保持715/900；高冲突验证1380/2944、家族宏TCR44.5461%，低于旧模型1410/2944、45.2379%。相同参数/新采样器、仅用原训练数据的控制为1417/2944、45.4613%。因此**本阶段不能声称加数据改善了泛化，v2不作为推荐版本**。

补采样共生成9286行额外标签；重训高冲突1374/2944、44.2308%，没有改善，未用于v2最终权重。v2最终仍为7890基础行。学习种子43/44与42相同。完整失败和消融记录保存在运行目录，不删除或改写历史制品。

后续保留同一数据划分、候选、24维特征、求解器与物理核验，只调整离线监督目标：

1. 按 `(lineage_group_id, state_hash)` 分组，只使用候选标签确有差异的状态；平标签只说明当前采样候选并列，不要求模型拟合某个绝对分数。
2. 比较两种目标：同状态标签减均值后乘剩余任务数，得到相对额外完成任务数；或用并列平均秩映射到[-0.5,0.5]。两者只读训练标签，均保留同状态的候选优劣顺序。
3. 重算有效来源/状态的等权训练权重。预定两目标各15/31叶，共4组；沿用180轮、learning_rate=0.05、min_samples_leaf=5、L2=1、seed42。该后续方案是在观察v2退步后提出，不能伪称最初就预注册，也不能把开发验证当未见最终测试。
4. 更严格发布门槛：原验证总完成数不低于v1，高冲突总完成数不低于v1，高冲突家族宏TCR严格提高，否则不登记新版。分数只是排序值，可为负；在线直接使用冻结模型分数，没有规则替代或规则兜底。
5. 新模型使用独立ID `lavis-v3-ranking`，manifest记录训练目标变换、有效训练行/家族和离线脚本SHA；原始标签仍是同一版本，不覆写缓存，不改变推理合同。

## 9. 最终推荐模型与验证结果

最终冻结 `lavis-v3-ranking`，权重SHA-256：`e8d83ae7dd56af6571a8bbecf2c9705dc89d7f814c59d8b1c5b3d16b1085487c`。使用同状态相对额外任务数目标、31叶HGB，其余参数见第8节。训练白名单124场景/92家族，但真正有排序信号的为393状态、3133行、46个有效家族（包含原14和新32家族）；不能把被过滤的平标签说成有效训练样本。

相对旧模型，新版多完成55个任务、家族宏TCR提高2.0991个百分点，原验证整体保持不变。新16家族中14提高、2下降（F036与F046）；四类场景的家族均值均提高。与相同目标/参数但没有新增数据的控制相比，提高130个任务、4.1388个百分点；该控制没有独立调参，不能外推成所有旧数据训练方案的上限。

与固定稀缺度控制总完成数相同，只在家族宏TCR上小幅提高约0.2830个百分点；**尚未证明优于所有规则或传统算法**。最终20测试未用。上述提升是经开发验证选择后的证据，不能当作独立最终测试结论或统计显著性结论。
