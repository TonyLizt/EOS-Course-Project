# 基础调度算法接入说明

新增 `fcfs`、`sjf`、`priority`、`edf`、`llf`、`hrrn` 六种基础算法，版本 `basic-1`。原13种比较算法和两个初始模型保留。`FCFO`、`FIFO`、`FCFS`在请求入口和旧工厂规范化为 `fcfs`，不会以多个别名重复计为不同算法。

## 卫星场景中的语义

这些是适用于离线卫星可见窗口的非抢占式基础策略。每轮重新检查未安排任务的可行观测/下传组合，取最早的受检可执行时刻，只在此时可执行的任务之间按基础策略派发一项，然后更新资源占用。不同卫星可以同时观测，不将全系统串行为一颗卫星；没有机会的任务不会阻塞其他任务。

- 到达时间：该任务首个观测窗口开始时间。数据集没有单独的CPU作业到达时间字段。
- 服务时间：`required_duration`，即连续观测时长，不将等待下传时间算作CPU服务时间。
- 截止期：该任务最后一个观测窗口结束时间，指观测机会的边界，不宣称为业务交付截止期。
- FCFS：到达时间升序；同到达时间按原任务输入顺序。
- SJF：服务时间升序；优先级调度：`priority`降序。
- EDF：截止期升序；LLF：截止期减当前派发时刻减服务时间，升序。
- HRRN：`1 + max(0, 当前派发时刻−到达时间)/服务时间`，降序，每轮重算。
- 其他策略同分时先到达时间，再输入顺序。相同场景和参数下固定排序；不使用随机打乱。

连续曝光不能任意拆分，因此没有将CPU抢占、SRTF或时间片轮转直接套到观测片段上。

## 与公共目标、数据和已有算法的关系

新算法直接实现 `Solver.solve`，也提供旧 `search` 工厂接口。复用原 `observation_at_index` 提取真实采样网格及角度，所有候选通过原 `ConstraintModel`；来源ID、下传字段、资源消耗及输出结构保持一致。接受所有原有场景格式，不增加数据必填字段，不修改场景、来源侧车或模型。

基础策略保留自身队列规则，公共 `ObjectiveModel` 仅用于同一任务、同一开始时间的可行放置选择，例如均衡权重可选择另一颗空闲卫星。不同目标仍按原实验条件隔离比较。这些算法不会伪造R1适配快照，也不声称对任意公共目标执行全局优化；原13种算法继续使用原来的R1适配路径，原冻结模型源码与训练域限制不变。

不消耗或继承初始模型计划，网页 `uses_initial_schedule=false`。仍记录实验公共初始模型字段，以保持现有比较条件和历史格式。基础算法在两个初始模型条件下可以得到相同结果，这是预期行为。

若场景中的任务时长、优先级相同，或可见机会互不冲突，不同基础策略可能得到相同计划。这不表示算法未执行；带冲突且时长/优先级不同的专项测试验证各自的派发规则。

支持无地面站和有地面站场景。存在地面站时必须同时找到满足下传时长及共享资源约束的通信窗口，不能以缺少下传的观测冒充完成。敏捷卫星使用真实网格，非敏捷卫星保持原固定居中规则。正式/工程核验/规划预览继续采用原数据准入和独立Verifier；接入新算法不会把未认证数据升级为正式认证数据。

## 参数与预算

| 参数 | 默认 | 范围 | 含义 |
|---|---:|---|---|
| `max_candidates_per_task` | 128 | 1–512 | 每轮每任务完整候选检查上限 |
| `max_windows_per_task` | 32 | 1–256 | 每轮尚未过期的窗口检查上限 |
| `max_positions_per_window` | 8 | 1–64 | 每窗口真实网格放置锚点上限 |

候选围绕当前时刻、资源释放/姿态切换时刻及均匀锚点构造，不展开整个时间网格。窗口按时间选择，各窗口放置交错检查。该方法有界，可能遗漏未检查的可行机会，不保证最早可行点或全局最优。预算耗尽返回已接受的可行部分计划；协作取消抛出取消异常，继续由原Worker/Controller决定终态。`solver_diagnostics.basic_scheduler`记录策略、派发顺序、候选检查数和预算退出标记，不作为物理证据。

敏捷卫星在 `earliest` 模式下从窗口最早网格点尝试，`center` 模式下从居中网格点及其后的位置尝试；旧命令行的 `latest` 模式选取窗口内最后一个可容纳完整观测的网格点。非敏捷卫星在各模式下始终仅允许原固定居中位置。

## 网页和命令行

重启现有后端、刷新网页，在“新建实验”中选择基础算法，可展开配置候选上限。也可向已有实验追加算法，或建立临时初始模型对照。后端清单驱动所有页面的名称和参数，结果比较、JSON/CSV导出、Gantt和Cesium使用原计划格式。

历史实验继续按原快照读取；跨代码版本追加仍遵守原来的源码身份和同条件校验。若旧实验提示版本不一致，应新建实验，不修改历史记录绕过比较规则。

单次提交及临时对照最多32项，默认待运行队列32项；Worker并发数没有随算法数量上调。自定义较小队列容量仍会按原机制返回队列已满。

```bash
python main_scheduler.py --algos fcfs sjf priority edf llf hrrn
python -m unittest discover -s tests -p test_basic_algorithms.py -v
node --test --test-isolation=none tests/basic_algorithms.test.cjs
```

真实集成验证使用 `scripts/validate_basic_schedulers.py`，参数指定公开开发场景目录、可选的冻结模型目录和一个尚不存在的产物目录。验证通过真实API、独立Worker、独立物理采样及导出链路；冻结最终测试集不用于开发验收。
