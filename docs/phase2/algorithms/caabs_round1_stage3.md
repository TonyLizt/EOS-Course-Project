# CAABS 阶段3：搜索配额评估与默认配置冻结

在阶段1和2独立消融完成后，使用阶段2提交95e3d39的冻结实现，比较8×8、4×4、16×8、8×4（Beam×可行分支）。uniform/clustered×20/100/300，每格一次，共24组，2秒，原评分不变，全部公共模型回放通过。
原始参数、指标和原始计划摘要见[固定变体](caabs_round1/width_variants.json)、[数据](caabs_round1/width.json)、[表格](caabs_round1/width.md)。末尾专项测试与最后几个短预算任务存在少量执行时间重叠，因此该轮是参数探索，不作为最终独立串行性能证据；最终矩阵独立串行重复执行。

扩大Beam没有普遍收益。4×4是低RT备选，但小型TP均值103低于16×8/8×4的106；对两种开发族的一次观测不足以证明跨域最优。保留原8×8默认值以减少未经验证的配额变化，不宣称其最优。

默认冻结：beam_width8、branch_limit8、candidate_check_limit16、max_candidates16、max_windows32、conflict_prefilter开启；candidate_diversity开启、task_order=scarcity、greedy_incumbent开启、incremental_keys开启、incremental_objective关闭。
旧机制单测通过显式id/无greedy/无增量配置继续验证原有分支语义，新默认单测验证确定性、完成数优先、可行性、正常进度和贪心阶段取消。专项63/63通过，0跳过，1.246秒。

没有同时加入Beam多样性配额、动态下传枚举和局部替换：当前证据最明确的是键缓存和初解，加入这些机制会引入新的候选接口与预算分配，且公共约束只占基线少部分时间。这些仍是后续独立实验方向，不把未实施机制记作本轮成果。
仍有可变嵌套姿态，未证明安全共享，保留深复制；没有按场景ID调参或修改数据。之后仅做最终矩阵、独立物理核验和完整回归；若发现失败，修复后重新冻结受影响结果。
