# 并行实验、结果评分与 LAVIS 搜索优化交接

日期：2026-10-20。基于 main `82bb261`（含 PR #29），分支 `feat/parallel-ranking-lavis-optimization`。本轮不训练、不生成场景，不读取冻结测试，不迁移数据库。2026-10-20 李泽同已授权提交、推送并创建 PR，合并由审核后决定。

## 1. 网页怎么使用

1. 正常停止旧后端，等待退出后用原启动命令重启；不要删除锁。源码身份变化后，已运行的服务不能直接用于新实验。
2. 在控制台展开“并行执行设置”，设置并发 Worker 数。正常启动默认 2，可选 1—8。每项实验的算法任务共享这个池，临时对照也共享，避免各开一个池造成超额运行。
3. 创建实验后，在结果比较区选择综合分、完成率、收益、等待时间、耗时等排序项及方向。排序只作用于同条件组；失败或无有效指标的结果排在组末。
4. 使用 LAVIS 时选择已有 `lavis-v3-ranking`，展开参数，设置 `search_mode=multistart`、`candidate_strategy=expanded`、`max_branches=8`。继续使用完成率目标、earliest、默认约束和无地面站场景；本轮验证预算为 30 秒。

旧默认仍是 `greedy + configured`；可以单独切换搜索或候选策略做消融。旧模型文件和场景无需复制更新；仅克隆代码的组员仍需单独获取已有模型与公开数据。

## 2. 并行执行设计与限制

Controller 最多维护 8 个轻量管理线程，实际计算由独立 spawn Worker 进程执行。领取记录串行，每条任务只启动一次 attempt；每个槽位拥有独立 IPC、核验槽位和恢复租约。槽位 0 保留旧租约路径，其他租约位于运行目录 `worker-slots/`。停机等待所有执行/核验线程并回收 Worker，再释放单实例锁；启动恢复全部槽位。SQLite 事务及终态导出仍受原边界保护。

并发数包含正在执行和核验的槽位。调低数值不会终止已有任务；须等活动任务减少后才领取新任务。取消只影响指定 run。队列容量仍沿用原设置；本轮没有承诺无限排队或调度公平性。

- GET `/api/execution-settings`：并发上限、活动数量、槽位 run_id。
- PUT 同路径，JSON `{"max_workers": 2}`：立即调整并保存到运行目录 `execution-settings.json`；整数范围外返回 422。
- 启动取值优先级：`EOS_MAX_WORKERS` > 保存文件 > 2。环境变量是启动覆盖，网页仍可调整本次进程；保留变量时下次重启重新按变量取值。
- 代码直接构造 Settings 的默认值仍为 1，以兼容已有嵌入与测试；常规服务通过 from_env 默认 2。
- `EXECUTION_RESOURCES` 事件记录派发时上限、活动数与槽位；API/JSON导出可查。并行有 CPU/内存竞争，正式比较耗时请设为 1，不能将并行耗时提升解释为算法优化。

## 3. 综合分与排序口径

`综合分 = 70 × TCR + 20 × TP/场景全部任务优先级之和 + 10 × (1 − TM)`。

TCR 为完成率；TP 为已完成任务收益；TM 为归一化等待时间，越小越好。分数使用固定绝对归一化，不随参赛算法增删而改变，耗时 RT 不参与总分。总优先级为 0 时收益项计 0，此特殊场景最高 80 分。

评分来自成功实验的已核验指标；来源不存在、场景 SHA 不匹配、指标无效或缺计划时显示无评分，不伪造 0 分。JSON 含 `ranking_score`、策略版本与归一化分母；CSV 增加分数及策略版本。原指标和算法优化目标不变，也不把展示分数当成连续物理认证。

同条件比较包含场景 SHA、物理和姿态版本、源码身份、约束、种子、预算、初始模型、核验类型及派发时并发上限等。不同组有分组提示，不混作一张总榜。并发上限相同仍可能有不同资源竞争，精确耗时比较应串行。

## 4. LAVIS 的变化

原权重、24维特征、训练域和模型清单保持原样。多分支先完成原候选上的模型贪心路径，保留可行 incumbent；扩展时尝试已有计划补排与全新模型路径，再对部分前缀尝试模型第二/第三候选并继续模型排序。按完成数、收益、开始时间保留更好计划，预算到达返回当前可行最优，取消继续传播。没有调用传统算法替代模型。

扩展候选仍使用原窗口的真实扫描网格和姿态切片，增加中点、尾部、四分之一及四分之三附近位置，逐项过共享可行性检查。每任务上限 96、全池 8192；原策略仍为每任务 32、全池 4096，每任务最多选择 16 个窗口。窗口先覆盖后加位置，避免某个早期窗口挤占全部名额。

这是复用模型的新推理策略，候选分布发生变化；不能说模型被重新训练或已证明泛化提升。分支数 1—32，默认 8，属于额外替代分支上限，不包括保留原路径和扩展基础路径。
